## 3. Схема бази даних (Таблиці Частини 2)

```sql
-- 1. Таблиця замовлень
CREATE TABLE orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    customer_id INTEGER,
    customer_name TEXT NOT NULL,
    customer_phone TEXT NOT NULL,
    customer_address TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'Нове',
    total_price REAL NOT NULL,
    coupon_code TEXT,
    discount_amount REAL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (customer_id) REFERENCES customers(id) ON DELETE SET NULL
);

-- 2. Таблиця зв'язку замовлень і товарів (Many-to-Many)
CREATE TABLE order_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL DEFAULT 1,
    price REAL NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);

-- 3. Таблиця промокодів (Рівень 3)
CREATE TABLE coupons (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    code TEXT NOT NULL UNIQUE,
    discount_percent INTEGER NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 4. Відповіді на контрольні запитання

1. **Що таке база даних і СКБД? Чим вони відрізняються?**
   - *База даних (БД)* — це структурована сукупність організованих даних, що зберігаються в електронному вигляді відповідно до визначеної моделі даних.
   - *СКБД (Система керування базами даних)* — це програмне забезпечення (наприклад, SQLite, PostgreSQL, MySQL), яке надає інтерфейси та механізми для створення, читання, модифікації, захисту й керування даними в БД.
   - *Відмінність:* БД — це безпосередньо самі дані та їхня структура, а СКБД — програма-інструмент, яка цими даними керує.

2. **Що таке реляційна модель даних?**
   - Реляційна модель базується на математичному понятті відношення (relation). Дані подаються у вигляді двовимірних таблиць, що складаються з рядків (кортежів/записів) та стовпців (атрибутів/полів). Таблиці пов'язуються між собою за допомогою спільних ключів (первинних і зовнішніх).

3. **Що таке первинний і зовнішній ключі?**
   - *Первинний ключ (PRIMARY KEY)* — це атрибут або комбінація атрибутів, яка однозначно ідентифікує кожний окремий рядок таблиці (наприклад, `id` в таблиці `orders`). Первинний ключ завжди унікальний і не може містити `NULL`.
   - *Зовнішній ключ (FOREIGN KEY)* — це колонка, яка містить значення первинного ключа іншої (батьківської) таблиці (наприклад, `order_id` в таблиці `order_items` посилається на `orders.id`). Він забезпечує посилальну цілісність (referential integrity) між даними.

4. **Як реалізувати зв'язок «багато-до-багатьох» між замовленнями й товарами?**
   - Оскільки одне замовлення може містити декілька товарів, а один і той самий товар може бути замовлений у багатьох різних замовленнях, безпосередньо зв'язати ці дві таблиці неможливо.
   - Зв'язок реалізується через **проміжну таблицю (junction table)** — у нашому проєкті це `order_items`. Вона містить зовнішні ключі `order_id` та `product_id`, що посилаються на батьківські таблиці, а також атрибути конкретного зв'язку: кількість купленого товару `quantity` та фіксовану ціну на момент замовлення `price`.

5. **Що означає абревіатура CRUD і яким SQL-командам відповідає?**
   - **C**reate (Створення) &rarr; `INSERT`
   - **R**ead (Читання/Вибірка) &rarr; `SELECT`
   - **U**pdate (Оновлення) &rarr; `UPDATE`
   - **D**elete (Видалення) &rarr; `DELETE`

6. **Переваги та обмеження SQLite:**
   - *Переваги:* не потребує окремого сервера чи служби, нульова конфігурація, уся база зберігається в одному файлі на диску, надзвичайно висока швидкість читання, вбудована у стандартну бібліотеку Python (`sqlite3`).
   - *Обмеження:* блокування всього файлу бази при операціях запису (writer lock), що робить SQLite непридатною для високонавантажених вебсайтів із тисячами одночасних записів; спрощена типізація стовпців (dynamic typing).

7. **Що таке SQL-ін'єкція і як захищають параметризовані запити?**
   - *SQL-ін'єкція* — вразливість безпеки, при якій зловмисник передає через користувацьке поле фрагмент SQL-коду, що змінює логіку виконання оригінального запиту до БД (наприклад, викрадення або видалення даних).
   - *Параметризовані запити* використовують плейсхолдери (знак `?` у SQLite). СКБД спочатку компілює шаблон SQL-запиту, а потім підставляє параметри як чисті дані. Навіть якщо рядок містить спеціальні символи або команди на кшталт `'; DROP TABLE orders; --`, вони інтерпретуються суто як текст, а не як інструкції.

8. **Навіщо відкривати й закривати з'єднання з БД для кожного запиту та викликати commit()?**
   - Відкриття з'єднання в рамках контексту запиту Flask (через `g.db`) і закриття в `teardown_appcontext` забезпечує ощадливе використання оперативної пам'яті, запобігає блокуванню файлу бази даних і конфліктам між паралельними потоками/користувачами.
   - Метод `commit()` явно фіксує всі зміни поточної транзакції у файлі бази даних на диску. Без виклику `commit()` транзакція вважається незавершеною і скасовується (rollback), а всі операції `INSERT`, `UPDATE` або `DELETE` втрачаються.
